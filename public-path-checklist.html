Check one public path before proposing a bigger change.

This one-page checklist helps an operator see whether a visitor can connect a visible promise, one next action, and the immediate destination without guessing.

Public-only and observational. Use visible page language and destinations only. Do not sign in, submit forms, use analytics, test checkout, or claim a business is losing money. A checked box is a cue to investigate—not proof of an outcome.

One-Page Public Path Check

Print this page. Review one page, one visitor, and one intended next action. Mark only what a public visitor can observe.

Public page / path
Visitor
Intended next action

1. Promise

Can a visitor see what this page is for before needing to act?

The headline or first cue names a specific outcome or use.
The visitor can tell who the page is for.
The next action does not promise more than the page explains.

2. Primary action

Can a visitor identify one sensible next step?

The primary control uses a concrete verb and outcome.
Competing actions are visibly secondary or clearly different.
The action is visible without hunting through the page.

3. Destination

Does the click lead where the visible cue says it will?

The destination preserves the original promise or names the change.
The destination makes the next choice understandable.
A public visitor can return or choose another route without confusion.

4. Immediate handoff

Is the first moment after the action explained?

The page states what opens, happens, or is requested next.
Any public requirement is visible before the visitor commits.
The path does not rely on unexplained jargon or hidden context.

Smallest proportionate next move

If one item is unclear: copy the exact public cue, identify the mismatch, and draft one smaller clarification. Do not jump from an observation to a redesign, accessibility/compliance claim, security claim, or performance claim.
